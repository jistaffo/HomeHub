# `<room-planner>`

A dependency-free custom element for laying out rooms as draggable,
resizable rectangles on a real-world (feet) grid. No build step, no
framework, no external libraries — drop `room-planner.js` into any page.

**To just use it, double-click `standalone.html`.** It's the same tool
as one self-contained file with no external files to load, so it works
straight from disk in any browser — no server, no build step, nothing
to install. It saves your layout automatically in that browser.

(`demo.html` is the same demo but loads `room-planner.js` as a real ES
module — the way you'd actually embed this in another app. That only
works served over `http://`/`https://` (e.g. `python3 -m http.server`),
because browsers block ES module loading from a page opened directly
via `file://`. If you just want to use the tool, use `standalone.html`
instead.)

## Why

You want a floor plan you can actually push around by hand — drag rooms
into place, stretch a wall by dragging its edge, and see the real
dimensions and square footage update as you go — rather than a static
diagram someone (or some AI) generated by guessing your layout.

## Quick start

```html
<room-planner id="planner"></room-planner>
<script type="module">
  import "./room-planner.js";
  const planner = document.getElementById("planner");
  planner.addEventListener("change", (e) => {
    console.log("new layout:", e.detail.state);
  });
</script>
```

That's it — with no further setup it starts from a small generic layout
(a living room, bedroom, bathroom, hallway, a door, and a window).

## Core interactions

- **Drag** anywhere on a piece's body to move it.
- **Resize from any of 8 handles**: the 4 corners resize both
  dimensions (the opposite corner stays put); the 4 edge midpoints
  resize just that one side (the opposite edge stays put).
- **Double-click a piece to rename it** right on the canvas (Enter
  commits, Escape cancels). The side panel can also rename it, plus set
  exact width, height, and position by typing numbers.
- Movement and resizing **snap to a 0.5 ft (6") grid**.
- Dimensions and square footage are shown live, updating **during**
  the drag/resize, not just after you let go.
- Pieces are clamped to the canvas and can't be resized below a
  sensible minimum.
- Works identically with mouse, touch, and pen (built on the Pointer
  Events API).

## Public API

### Properties

| Property | Type | Description |
|---|---|---|
| `.initialState` | `Piece[]` | Starter layout, read once when the element first connects (or whenever set before that). Falls back to a small generic layout if never set. |
| `.referenceNotes` | `{value, label}[]` | Optional sidebar list of reference measurements (e.g. real tape measurements you've taken). Omit or pass `[]` to hide the panel. |
| `.notes` | `string` | Optional freeform notes shown in the sidebar. Omit to hide the panel. |
| `.types` | `object` | Optional override/extension of the room-type catalog (see below). |

### Attributes

For pure-HTML usage with no JavaScript beyond the `import`, these mirror
the properties above and are read once at connect:

- `initial-state="[...]"` — JSON-encoded array of pieces
- `heading="..."` — overrides the default `<h1>` text
- `subheading="..."` — overrides the default instructional copy

### Methods

- **`getState()`** → `Piece[]` — the current layout (a copy, safe to mutate).
- **`setState(pieces)`** — replace the layout programmatically. Does
  **not** fire `"change"` — this is inbound hydration, not a user
  edit, and firing it would create a feedback loop with whatever store
  called `setState()` in the first place.

### Events

- **`"change"`** — `CustomEvent<{state: Piece[]}>`, fired once per
  *committed* user gesture: a drag release, a resize release, or an
  add/delete/rename/typed-dimension edit. Never fired on every
  pointer-move — it's already debounced to one event per gesture.

### Piece shape

```ts
{
  id: string,
  type: string,     // key into the type catalog, e.g. "bedroom"
  label: string,    // user-editable display name
  x: number, y: number,   // position, in feet
  w: number, h: number,   // size, in feet
}
```

### Type catalog

Each entry in `.types` (or the built-in `DEFAULT_TYPES`, also exported
from the module) has this shape:

```ts
{
  label: string,    // shown in the "Add piece" dropdown and as a default label
  tag: boolean,      // true = a small point feature (door/window/...) with
                      // no resize handles and no area counted in the total
  w: number, h: number,  // default size in feet when added
  group?: string,    // visual color grouping, e.g. "common" | "bed" | "wet" | "circulation"
}
```

The built-in catalog covers common room types (living room, kitchen,
dining room, office, sunroom, hallway, stairs, utility, laundry room,
mudroom, garage, closet, bedroom, bathroom) plus point tags (door,
window, exterior feature). Pass `.types` to add your own or override
any of these — it's merged over the defaults, so you only need to
specify what you're changing.

## Theming

Every color is a CSS custom property on the host element, with light
and dark defaults built in (respecting `prefers-color-scheme`, and
overridable via `data-theme="light"` / `data-theme="dark"`). Override
any of them from your own stylesheet:

```css
room-planner {
  --rp-accent: #7C3AED;
  --rp-paper: #ffffff;
}
```

See the `:host` rule at the top of `room-planner.js` for the full list
of `--rp-*` variables (paper/panel backgrounds, ink/text colors,
per-room-type group colors, the danger/delete color, and so on).

## Persistence

This component holds no storage or network code of its own — that's
intentional, so it can drop into any app's existing save flow. Listen
for `"change"` and persist however you like; call `.setState()` to push
external updates back in. `demo.html` shows the simplest possible
version of this using `localStorage`.
